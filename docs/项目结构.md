# 项目结构

```
campus-knowledge-rag/
├── README.md                项目主文档（快速开始、指标、关键设计）
├── NOTICE.md                语料来源与使用声明
├── LICENSE                  MIT
├── requirements.txt         Python 依赖
├── .gitignore               排除索引生成物与本机配置
├── .gitattributes           统一换行符为 LF
├── docs/
│   └── 项目结构.md           本文件
├── data/
│   └── docs/                语料：30 份校园公开文档（doc-001.txt ~ doc-030.txt）
├── rag/                     RAG 包
│   ├── config.py            所有可调参数 + 阈值标定说明
│   ├── cleaner.py           语料清洗（规则 + 跨文档模板行检测 + 标题抢救）
│   ├── chunker.py           按条款边界切分，带 overlap 与出处 metadata
│   ├── embedder.py          向量化（API / 本地 n-gram 双实现，自动降级）
│   ├── store.py             向量索引 + 余弦检索 + 去重 + 两道拒答闸门
│   ├── generator.py         生成（提示词 + 引用装配 + 抽取式兜底）
│   ├── pipeline.py          主流程，对外只暴露 ask()
│   ├── server.py            FastAPI 服务
│   ├── eval/
│   │   └── questions.json   评测集（30 道库内 + 12 道库外，人工标注应命中文档）
│   ├── cli_index.py         建索引
│   ├── cli_ask.py           问答（单次 / 交互式）
│   ├── cli_search.py        检索调试（只检索不生成）
│   ├── cli_eval.py          评测（Recall@K / MRR / 拒答准确率）
│   ├── cli_calibrate.py     拒答阈值标定
│   ├── cli_clean.py         清洗效果预览
│   ├── cli_chunks.py        切分结果预览
│   ├── cli_margin.py        诊断：分数间隔是否为有效判据
│   ├── cli_diag_coverage.py 诊断：覆盖率闸门误杀
│   └── data/                索引生成物（vectors.npy / chunks.json / index_meta.json）
│                            ⚠ 不入版本库，由 cli_index 生成
└── tests/
    └── test_rag.py          37 项测试，含 2 个历史 bug 的回归用例
```

## 数据流向

```
data/docs/*.txt
     │  cleaner.clean_corpus()      规则清洗 + 跨文档模板行检测
     ▼
   干净正文
     │  chunker.build_chunks()      按条款边界切分
     ▼
  151 个 Chunk（带 doc_id / title / url / chunk_index）
     │  embedder.encode()           2048 维归一化向量
     ▼
  VectorStore（vectors.npy + chunks.json）
     │  store.Retriever.retrieve()  余弦检索 + 去重 + 两道闸门
     ▼
  Top-K Hit
     │  generator.generate()        提示词 + 引用；无依据则拒答
     ▼
     Answer
     │
     ├─→ cli_ask / cli_search       命令行
     └─→ server.py                  HTTP
```

## 几个约定

- **索引是生成物，不入库**。克隆后跑一次 `python -m rag.cli_index` 即可重建
  （0.5 秒）。这样做的好处是 README 里的指标必然来自当前代码 + 当前语料，
  不会出现"仓库里的索引是旧的、指标对不上"的情况。
- **诊断脚本保留在仓库里**。`cli_margin.py` 和 `cli_diag_coverage.py` 是我
  试过但**失败**的方案（分数间隔、离群 z 值都无法区分库内/库外问题），
  保留是为了记录"为什么最终选了现在这个做法"，而不是删掉了事。
- **语料与代码分离**。语料放在仓库根的 `data/docs/`，代码放在 `rag/`；
  `config.py` 会自动探测语料位置，也支持用 `RAG_DOCS_DIR` 环境变量覆盖。
