# 校园知识问答助手（RAG）

基于 RAG（检索增强生成）的校园文档问答服务。学生用口语提问，系统从校园公开文档中
检索依据、生成**带出处引用**的答案；查不到就**明确拒答**，不编造。

**为什么做**：新生高频问题（转专业条件、助学贷款、体质测试安排）散落在数十份校园
文件里，官网站内搜索不可用，只能靠问学长。而政策类问答一旦编造，代价比答不出更大
—— 所以这个项目的重点不是"调通大模型"，而是**让答案可核对、让无依据的问题拒答**。

## 效果

42 道评测题（30 道库内有答案 + 12 道库外，逐题人工标注应命中文档）：

| 指标 | 数值 |
| --- | --- |
| Recall@5 | **100.0%** |
| MRR | **0.950** |
| 拒答准确率 | **91.7%** |

复现：`python -m rag.cli_eval`

## 快速开始

不需要 API Key、不需要向量数据库、不需要下载模型权重。

```bash
pip install -r requirements.txt

python -m rag.cli_index                      # 建索引（约 0.5 秒）
python -m rag.cli_ask "转专业需要什么条件"      # 提问
python -m rag.cli_eval                       # 看指标
```

问一个库里没有的问题（如 `今天杭州天气怎么样`），它会拒答并建议咨询教务处。

依赖只有 `numpy` 和 `requests`；`fastapi`/`uvicorn`/`pydantic` 仅在跑 HTTP 服务时需要。

## 工作方式

```
data/docs/*.txt
   │ cleaner    规则清洗 + 跨文档重复行检测 → 剔除站点模板噪声
   │ chunker    按「第X条」等条款边界切分，保留出处 metadata
   │ embedder   API embedding 或本地字符 n-gram 双实现
   │ store      余弦检索 + 相邻块去重 + 两道拒答闸门
   │ generator  提示词 + 强制引用 + 抽取式兜底
   ▼ pipeline.ask()  →  CLI / FastAPI
```

默认走**完全离线**链路（本地 n-gram 向量 + 抽取式生成），配上 Key 自动升级为
语义检索 + 大模型总结，业务代码零改动。

### 接入大模型 / 语义向量化

```bash
export RAG_LLM_API_KEY=sk-xxx          # 生成（配了才有总结式回答）
export RAG_EMBED_API_KEY=sk-xxx        # 向量化（配了才有语义泛化能力）
```

> ⚠ **换了向量化方式必须重新标定拒答阈值**：`python -m rag.cli_calibrate`。
> 不同向量的余弦尺度完全不同，沿用旧值会大面积误判。

## 四个关键设计

**1. 按条款边界切分，不按固定长度硬切** —— 校园制度文档有「第X条」「一、」这类天然
结构，一个条款通常就是一个完整语义单元。按长度硬切会切出半句话，检索到残缺内容。

**2. 跨文档重复行检测清模板噪声** —— 采集下来的网页正文混着导航栏。判断方法不需要
事先知道模板长什么样：**一行若出现在 ≥25% 的文档里，它就是站点模板**。配合规则清洗，
实测删掉 9% 无效字符，并顺带把标题抢救了回来。

**3. 拒答用两道闸，第二道只作用于低分带** —— 相似度阈值 0.11 由分布标定而非估算
（库内 min=0.1188，库外 max=0.1042）。光看相似度会有假阳性（问「怎么补办学生证」
命中《平安保险须知》），但覆盖率闸门一刀切又会误杀（实测把 Recall@5 从 100% 拉到
90%），所以只对 `score < 0.25` 的疑似命中施加覆盖率要求。

**4. 覆盖率用字符二元组，不用分词** —— 最初用"连续汉字串"当关键词，
「什么情况下不能转专业」整串被当成**一个词**，覆盖率算成 0，误杀 3 道正确结果，
且不会报错。改用二元组后不需要分词器，对「转专业 → 转专业实施办法」这类包含
关系也天然友好。此 bug 已加回归测试保护。

## 命令

| 命令 | 作用 |
| --- | --- |
| `python -m rag.cli_index` | 建 / 重建索引（语料或切分参数变了必须重跑） |
| `python -m rag.cli_ask "问题"` | 单次问答（不带参数进交互模式） |
| `python -m rag.cli_search "问题"` | 只检索不生成，调参用 |
| `python -m rag.cli_eval` | 评测：Recall@K / MRR / 拒答准确率 |
| `python -m rag.cli_calibrate` | 标定拒答阈值 |
| `python -m rag.cli_clean` | 预览清洗效果与标题识别 |
| `python -m rag.cli_chunks` | 预览切分结果 |
| `python -m rag.cli_margin` | 诊断：分数间隔是否为有效判据 |
| `python -m rag.cli_diag_coverage` | 诊断：覆盖率闸门误杀 |
| `python tests/test_rag.py` | 37 项测试 |
| `python -m rag.server` | 启动 HTTP 服务 |

`cli_margin` 和 `cli_diag_coverage` 是我**试过但失败**的方案（分数间隔、离群 z 值
都无法区分库内/库外问题），保留在仓库里是为了记录"为什么最终选了现在这个做法"。

## HTTP 接口

```bash
python -m rag.server
# 服务 http://127.0.0.1:8000    交互文档 http://127.0.0.1:8000/docs
```

`GET /health`、`GET /info`、`POST /ask`、`POST /retrieve`、`POST /rebuild`

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"转专业需要什么条件","top_k":3}'
```

返回带 `answer`、`citations`（含文档名与原始 URL）、`source`（`llm` / `extractive` / `refused`）。

## 目录

```
rag/                  RAG 包（config / cleaner / chunker / embedder / store / generator
                      / pipeline / server + 9 个 cli_* 脚本）
rag/eval/questions.json   评测集（30 库内 + 12 库外，人工标注）
tests/test_rag.py     37 项测试
data/docs/            30 份校园公开文档
```

索引产物（`rag/data/`）不入版本库，由 `cli_index` 生成 —— 这样 README 里的指标
必然来自当前代码 + 当前语料。

## 数据来源

语料采集自杭州师范大学**公开可访问**的页面（教务处、党委学生工作部），
只抓公开内容，不登录、不绕过任何访问控制。原始页面 URL 记录在每份文档的元信息里。

## 已知局限

1. **语料覆盖不全** 是最大短板。只有 30 份文档，**缺学生手册、培养方案、图书馆规则、
   宿舍管理规定** —— 教务处「规章制度」栏目翻到底也只有 8 篇，核心制度很可能未公开
   挂出；图书馆站点返回首页仅 2.9KB、零链接，无法采集。后果是「图书馆借书能借几本」
   这类问题只能拒答。**补语料的收益远大于调参。**
2. **「怎么补办学生证」被误答**，所以拒答准确率是 91.7% 而非 100%。命中文档正文含
   「学生」二字导致覆盖率虚高，本地字面向量下难以消除。
3. **同义改写会漏** —— 离线向量只做字面匹配（「挂科」vs「课程考核不合格」）。
4. **评测集偏小**（42 题），指标数量级可信，小幅波动不必当真。
5. **不支持多轮对话**，没有 query 改写与指代消解。

### 后续改进（按性价比）

补齐核心语料 → 接 API embedding 换语义检索（**记得重新标定阈值**）→ 加查询改写层
→ 多轮指代消解 → 评测集扩到 100+ 题
