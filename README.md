# 校园知识问答助手（RAG）

一个面向校园场景的检索增强生成（RAG）问答服务：学生用口语提问，系统从校园公开
文档里检索依据、生成**带出处引用**的答案；查不到就**明确拒答**，不编造。

**为什么做这个**：新生的高频问题（转专业什么条件、助学贷款怎么办、体质测试在哪测）
答案散在几十份学校文件里，官网站内搜索又不可用，只能靠问学长。而政策类问答一旦
编造，代价比答不出更大——所以这个项目的核心不是"调通大模型"，而是
**让答案可核对、让无依据的问题拒答**。

## 实测效果

用 42 道题评测（30 道知识库内确有答案的 + 12 道库外的，逐题人工标注应命中文档）：

| 指标 | 数值 |
| --- | --- |
| **Recall@5** | **100.0%** |
| **MRR** | **0.950** |
| **拒答准确率** | **91.7%** |

复现：`python -m rag.cli_eval`

## 快速开始

**不需要任何 API Key、不需要向量数据库、不需要下载模型权重。**

```bash
pip install -r requirements.txt

# 1. 构建索引（约 0.5 秒）
python -m rag.cli_index

# 2. 提问
python -m rag.cli_ask "转专业需要什么条件"

# 3. 看指标
python -m rag.cli_eval
```

第 2 步会输出答案 + **出处列表（含文档名和原始 URL）**。
问一个知识库里没有的问题（如 `今天杭州天气怎么样`），它会拒答并建议找教务处。

### 依赖很轻

## 两条运行链路

| | 向量化 | 生成 |
| --- | --- | --- |
| **默认（离线）** | 字符 n-gram 特征哈希 → 2048 维 | 抽取式：直接给最相关原文 + 出处 |
| **配 Key 后** | 真实 embedding API | 大模型总结式回答，带 `[1][2]` 引用 |

设计意图：**让整条链路（切分→清洗→检索→生成→评测）在零依赖、零成本、可复现的
前提下先跑通**，配上 Key 自动升级为语义检索，业务代码零改动。

离线向量化只做字面匹配，同义改写会漏（"挂科" vs "课程考核不合格"）。但校园制度类
文档的用词与提问重合度较高，所以实测召回仍然可用——这个取舍在
[`rag/config.py`](rag/config.py) 里有说明。

### 接入大模型 / 语义向量化

```bash
# 生成（配了才有总结式回答）
export RAG_LLM_API_KEY=sk-xxx
export RAG_LLM_MODEL=deepseek-chat

# 向量化（配了才有语义泛化能力）
export RAG_EMBED_API_KEY=sk-xxx
export RAG_EMBED_BASE_URL=https://api.deepseek.com/v1
export RAG_EMBED_MODEL=embedding-2
```

> ⚠ **换了向量化方式后必须重新标定拒答阈值**：`python -m rag.cli_calibrate`。
> 不同向量的余弦分布尺度完全不同，沿用旧阈值会大面积误判。详见 [关键设计 4](#4-拒答阈值必须标定不能估算)。

## 架构

```
校园公开网页
     │  采集
     ▼
┌─────────────┐
│  cleaner    │ 规则清洗 + 跨文档重复行检测 → 剔除站点模板噪声
└─────────────┘
     ▼
┌─────────────┐
│  chunker    │ 按「第X条」「一、」等条款边界切分，带 overlap 与 provenance
└─────────────┘
     ▼
┌─────────────┐
│  embedder   │ API embedding  或  本地字符 n-gram 特征哈希
└─────────────┘
     ▼
┌─────────────┐
│  store      │ 归一化向量矩阵 + 余弦相似度检索 + 覆盖率闸门
└─────────────┘
     ▼
┌─────────────┐
│  generator  │ 提示词工程 + 强制引用 + 无依据时拒答
└─────────────┘
     ▼
  pipeline.ask()  →  CLI / FastAPI
```

**当前规模**：30 份文档 → 151 个知识片段 → 2048 维索引。

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 清洗 | `rag/cleaner.py` | 规则清洗 + 跨文档模板行检测 + 标题抢救 |
| 切分 | `rag/chunker.py` | 条款边界优先切分，保留出处 metadata |
| 向量化 | `rag/embedder.py` | API / 本地双实现，自动降级 |
| 检索 | `rag/store.py` | 余弦检索 + 去重 + 两道拒答闸门 |
| 生成 | `rag/generator.py` | 提示词 + 引用装配 + 抽取式兜底 |
| 主流程 | `rag/pipeline.py` | 对外只暴露 `ask()` |
| 服务 | `rag/server.py` | FastAPI，5 个接口 |

## 四个关键设计

### 1. 按条款边界切分，不按固定长度硬切

校园制度文档有天然结构（「第X条」「一、」「（一）」）。一个条款通常就是一个完整
语义单元，按固定长度硬切会把条款切碎，检索到半句话。

实现：先按条款标记聚合成"条款单元"→ 条款内部按句子退让 → 最后才硬切；
另加 `chunk_overlap=80`，避免答案正好跨在边界上被截断。

### 2. 跨文档重复行检测来清模板噪声

采集下来的网页正文混着导航噪声。实测「课程思政教学研究中心」这类栏目名出现在
11 个页面上——它们会被算进相似度，严重污染检索。

**不需要事先知道模板长什么样**：一行若出现在 ≥25% 的文档里，它就是站点模板。
这个办法对任何 CMS 站点都适用。配合规则清洗，实测删掉 9% 字符，
并顺带把标题抢救回来了（原本全是"杭州师范大学教务处"，现在能识别出
《本科生转专业实施办法》这类真标题）。

### 3. 拒答用两道闸，第二道只作用于低分带

**第一道：相似度阈值 0.11**。不是估的——用 10 道库内题 + 10 道库外题对比分数分布：

```
库内问题（有答案）: min=0.1188  中位=0.1881  max=0.3285
库外问题（无答案）: min=0.0544  中位=0.0806  max=0.1042
                              ↑ 阈值取在空隙里
```

**第二道：关键词覆盖率，只作用于 `score < 0.25` 的情况。**

- *为什么需要*：光看相似度有假阳性——问「怎么补办学生证」会命中《平安保险须知》，
  分数 0.1191 刚好越线。
- *为什么不一刀切*：高分段存在覆盖率偏低却正确的结果（「转专业每学期可以填几个
  志愿」覆盖率仅 0.30，命中文档却完全正确）。一刀切实测把 **Recall@5 从 100% 拉到 90%**。

### 4. 拒答阈值必须标定，不能估算

不同向量化方式的余弦分布尺度**完全不同**。换成 API embedding 后沿用 0.11 会导致
**所有问题都被判为"有依据"，拒答功能直接失效**。

所以阈值标定是独立的一步：`python -m rag.cli_calibrate` 会扫描阈值空间，
输出使判别准确率最高的取值。相关诊断脚本还有 `cli_margin.py`（分数间隔/离群度）
和 `cli_diag_coverage.py`（覆盖率误杀）——后两个是我试过但**失败**的方案，
保留下来是为了记录"为什么选了现在这个做法"。

## HTTP 接口

```bash
python -m rag.server
# 服务：http://127.0.0.1:8000
# 交互文档：http://127.0.0.1:8000/docs   ← 浏览器里可直接点着测
```

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| GET | `/info` | 索引与链路信息 |
| POST | `/ask` | 问答（检索 + 生成 + 引用） |
| POST | `/retrieve` | 只检索不生成 |
| POST | `/rebuild` | 重建索引 |

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"转专业需要什么条件","top_k":3}'
```

```json
{
  "question": "转专业需要什么条件",
  "grounded": true,
  "answer": "……",
  "citations": [
    { "index": 1, "doc_id": "doc-001",
      "title": "普通高等学校学生管理规定",
      "url": "https://jwc.hznu.edu.cn/c/2017-09-12/1857835.shtml",
      "score": 0.1188 }
  ],
  "source": "extractive",
  "elapsed_ms": 2
}
```

`source` 取值：`llm`（大模型生成）/ `extractive`（离线抽取式）/ `refused`（拒答）。

## 测试

```bash
python tests/test_rag.py      # 37 项，覆盖 8 个模块
```

包含两个**历史 bug 的回归用例**：

1. **整串汉字被当单词**：最初用"连续汉字串"当关键词，「什么情况下不能转专业」
   整串被当成**一个词**，覆盖率算成 0，误杀 3 道正确结果。这类 bug 不报错，
   只能靠看逐题明细发现。
2. **夹文字的分隔线漏清洗**：`--------友情链接--------` 不是纯分隔线，
   用正则字符类判断会漏。改为"剥离装饰符后判断剩余内容"。

## 已知局限

如实记录，包括我试过但没成功的方案：

1. **语料覆盖不全**（最大的短板）。目前只有 30 份文档，**缺学生手册、培养方案、
   图书馆规则、宿舍管理规定**——教务处「规章制度」栏目翻到底也只有 8 篇，
   核心制度很可能没公开挂出；图书馆站点返回首页仅 2.9KB、零链接，无法采集。
   后果：问「图书馆借书能借几本」「宿舍可以住到什么时候」只能拒答。
   **补语料的收益远大于调参。**

2. **「怎么补办学生证」被误答**（所以拒答准确率是 91.7% 而非 100%）。
   命中的《平安保险须知》正文含「学生」二字，字面重叠导致覆盖率虚高。
   本地字面向量下难以消除，换语义 embedding 才是正解。

3. **同义改写会漏**。离线向量只做字面匹配。

4. **评测集规模偏小**（42 题）。指标数量级可信，小幅波动不必当真。

5. **不支持多轮对话**。没有 query 改写与指代消解，「那重修呢？」这类追问无法解析。

### 后续改进（按性价比排序）

1. 补齐核心语料（收益最大）
2. 接 API embedding 换语义检索 → **然后重新标定阈值**
3. 加查询改写层（用大模型把口语问题改写成检索友好查询）
4. 多轮对话的指代消解
5. 评测集扩到 100+ 题
